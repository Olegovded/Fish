# Запуск мини-приложения и привязка к боту

Приложение = один процесс: он и раздаёт мини-апп (веб-страницу, которую Telegram
открывает в окне), и обслуживает API с базой, и **сам привязывает кнопку меню к
боту при старте**. Отдельная настройка через BotFather не нужна.

Ниже — деплой на бесплатный **Render.com** (рекомендуется). Есть и вариант для
любого другого хостинга (Docker) и для своего VPS (см. низ файла).

---

## Вариант А — Render.com (бесплатно, рекомендуется)

В репозитории уже лежит `render.yaml` — Render всё поднимет по нему.

1. Заведите аккаунт на **https://render.com** (можно войти через GitHub).
2. **New → Blueprint**, подключите репозиторий `Olegovded/Fish`, ветку
   `claude/telegram-fishing-bot-mvp-27rotr`. Render увидит `render.yaml`.
3. При создании попросит задать секрет **BOT_TOKEN** — вставьте токен от
   @BotFather. `BOT_USERNAME=Ribaku_bot` уже прописан.
4. Нажмите **Apply**. Render соберёт и запустит сервис, выдаст адрес вида
   `https://ribaku-bot.onrender.com`.
5. **Готово.** Приложение само подставит свой адрес (`RENDER_EXTERNAL_URL`) и
   привяжет кнопку меню к боту. Откройте **@Ribaku_bot** в Telegram → снизу
   появится кнопка **«🎣 Открыть»**, а команда `/start` даст кнопку запуска.

Проверить, что всё поднялось: откройте `https://<ваш-адрес>/health` — должно
вернуться `{"ok": true}`.

> ⚠️ **Про бесплатный тариф Render:**
> - Сервис «засыпает» после ~15 минут без запросов и просыпается за 20–40 сек при
>   первом обращении — для теста это нормально.
> - Диск на free-тарифе **эфемерный**: при передеплое/перезапуске файл базы
>   `fishing.db` обнуляется. Для короткого теста ок; чтобы данные копились
>   постоянно — подключим бесплатную внешнюю базу (Supabase/Postgres) отдельным
>   шагом. Скажите — сделаю.

## Вариант Б — любой хостинг через Docker

В репозитории есть `Dockerfile`. На Railway/Fly.io/своём сервере:

- переменные окружения: `BOT_TOKEN`, `BOT_USERNAME=Ribaku_bot`,
  `WEBAPP_URL=https://<ваш-публичный-https-адрес>` (на Render он подставляется
  сам, на других хостингах укажите вручную);
- порт приложение берёт из `$PORT` (или 8080).

```bash
docker build -t ribaku .
docker run -e BOT_TOKEN=... -e BOT_USERNAME=Ribaku_bot \
           -e WEBAPP_URL=https://ваш-домен -p 8080:8080 ribaku
```

## Вариант В — свой VPS (для постоянной работы)

Мини-приложению нужен публичный **HTTPS**. Схема: домен + Nginx с сертификатом
Let's Encrypt, проксирующий на локальный порт приложения. Затем systemd-юнит
(`deploy/fishing-bot.service`) держит процесс запущенным. `WEBAPP_URL` = ваш
https-домен. Напишите — дам пошагово под вашего провайдера.

## Что нужно от вас (минимум)

Только **BOT_TOKEN** от @BotFather (уже есть) и пара кликов в Render по
шагам выше. Всё остальное — сборку, запуск, привязку к боту — приложение
делает само.
